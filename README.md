## คุณสมบัติ

- **หน้าแรก `index.html`**
  - Hero แสดงคะแนนรวมถ่วงน้ำหนักและสถานะแบบเรียลไทม์
  - การ์ดสรุปผล
  - แผนภูมิวงกลมภาพรวมน้ำหนักตัวชี้วัด (ฝั่งซ้าย) และเกณฑ์การประเมินผล (ฝั่งขวา)
  - ตารางเป้าหมายรวมแผนก O.A. พร้อมช่องกรอกผลการดำเนินงาน (%)
  - ตารางบันทึกผลการดำเนินงานรายเดือน (เลือกเดือนแล้วกรอกผลทั้ง 7 ตัวชี้วัด)
  - ตารางเป้าหมายบุคคลของหัวหน้าแผนกและเจ้าหน้าที่ O.A.
  - ฟอร์มบันทึกข้อมูลผู้รายงาน รอบเดือน และวันที่รายงาน
  - ปุ่มบันทึก / ล้างผล / พิมพ์รายงาน
- **หน้ารายงาน `performance.html`**
  - การ์ดประวัติพนักงาน (ภาพถ่าย รหัสพนักงาน และชื่อ-สกุล)
  - แดชบอร์ดผลรายเดือนและ Executive Summary
  - ตารางผลการดำเนินงานรายปี (ลำดับ / ตัวชี้วัด / ผลแยกตามเดือน / เฉลี่ยปี)
  - อัลบั้มภาพกิจกรรม 20 ภาพ พร้อมตัวกรองและ Lightbox
- ข้อมูลถูกคำนวณและบันทึกอัตโนมัติใน `localStorage` ของเบราว์เซอร์
- ตัวอักษรขนาดเล็กสุด 12px (ข้อความหลัก 13–14px) และใช้สีข้อความรองที่เข้มขึ้นเพื่อให้อ่านง่ายขึ้น
- ไม่พึ่ง CDN สำหรับ CSS (Tailwind ถูก build ไว้ในโปรเจกต์) ใช้เฉพาะ Google Fonts

## เริ่มใช้งาน

ต้องมี [Node.js](https://nodejs.org/) เวอร์ชัน 18 ขึ้นไป

```bash
npm install          # ติดตั้ง dependencies (ครั้งแรก)
npm run build        # build CSS
npm run preview      # เปิดเซิร์ฟเวอร์ที่ http://localhost:4173
```

โหมดพัฒนา CSS (watch):

```bash
npm run dev
```

> เปิดไฟล์ `index.html` โดยตรงผ่าน `file://` ได้ แต่แนะนำให้ใช้ `npm run preview` เพื่อให้เบราว์เซอร์โหลด assets ได้ครบถ้วน

## การแก้ไขข้อมูล KPI

ข้อมูลตัวชี้วัด น้ำหนัก เป้าหมาย และข้อมูลตัวอย่าง อยู่ใน `assets/js/data.js`

ตัวชี้วัด 7 รายการ (น้ำหนักรวม 100%):

| # | ตัวชี้วัด | น้ำหนัก |
| - | --- | --- |
| 1 | ดูออนไลน์ กล้องวงจรปิด สาขาศรีวิชัย | 10% |
| 2 | ดูออนไลน์ กล้องวงจรปิด สาขาท่าทอง | 10% |
| 3 | เปลี่ยนอุปกรณ์ เพิ่มความรวดเร็ว ระบบ POS | 30% |
| 4 | ความพึงพอใจของผู้ใช้งาน (แคชเชียร์) ระบบ POS (หลังจากปรับปรุงระบบแล้ว) | 10% |
| 5 | ระบบโทรศัพท์ภายในใช้งานได้อย่างมีประสิทธิภาพทุกจุด 100% | 10% |
| 6 | ระบบเสียงตามสายใช้งานได้อย่างมีประสิทธิภาพทุกจุด 100% | 10% |
| 7 | พัฒนาระบบสารสนเทศ HR (HRIS) | 20% |

```js
const KPI_ITEMS = [
  { id: "pos_upgrade", title: "เปลี่ยนอุปกรณ์ เพิ่มความรวดเร็ว ระบบ POS", weight: 30, target: 100, ... },
  // ...
];
```

แผนภูมิวงกลมภาพรวมน้ำหนักสร้างจาก `KPI_ITEMS` ใน `assets/js/app.js` (`renderWeightDonut`) โดยใช้สีและน้ำหนักของแต่ละรายการ จึงปรับตามข้อมูลได้อัตโนมัติ

- `weight` คือน้ำหนักของตัวชี้วัด (ผลรวมต้องเท่ากับ 100)
- `target` คือเป้าหมายขั้นต่ำที่ถือว่าบรรลุ (ปกติ 100)
- `DEFAULT_OVERALL` / `DEFAULT_PERSONAL` คือข้อมูลตัวอย่างเริ่มต้น
- `DEFAULT_MONTHLY_BY_KPI` คือผลรายเดือนตัวอย่างของแต่ละตัวชี้วัด (12 เดือน) ใช้สร้างตารางรายปี
  โดยกำหนดให้ **ม.ค.–มิ.ย. = 0** และ **พ.ย.–ธ.ค. = 0** ส่วน ก.ค.–ต.ค. คำนวณจาก `MONTHLY_GROWTH` คูณผลรวมปัจจุบัน
- `MONTHLY_OVERRIDES` ใช้กำหนดผลรายเดือนเฉพาะตัวชี้วัด เช่น HRIS: ก.ค. 70, ส.ค. 76, ก.ย.–ต.ค. 100
- `state.monthlyByKpi` เก็บผลรายเดือนที่ผู้ใช้บันทึก แยกตามรหัสตัวชี้วัดและเดือน (ม.ค.–ธ.ค.)
- `schemaVersion` ใช้ตรวจเวอร์ชันข้อมูลใน `localStorage` ข้อมูลเดิมจะถูก migrate อัตโนมัติเมื่อโหลด (v2: ม.ค.–มิ.ย. = 0, v3: ค่า HRIS ก.ค.–ต.ค., v4: พ.ย.–ธ.ค. = 0)
- `DEFAULT_MONTHLY` คือคะแนนถ่วงน้ำหนักรายเดือนที่คำนวณจาก `DEFAULT_MONTHLY_BY_KPI`
- ข้อมูลที่ผู้ใช้บันทึกจะถูกเก็บใน `localStorage` คีย์ `kpi-oa-2569-v1` (แยกตามเบราว์เซอร์และเครื่อง)

หลังแก้ไขไฟล์ JS ไม่ต้อง build ใหม่ (ยกเว้นแก้คลาส Tailwind ใน HTML/JS ให้รัน `npm run build:css`)

## การบันทึกผลรายเดือน

1. ไปที่หน้าแรก ส่วน **บันทึกผลการดำเนินงานรายเดือน**
2. เลือกเดือนที่ต้องการบันทึกจากช่อง **เดือนที่บันทึก**
3. กรอกผลการดำเนินงานของทั้ง 7 ตัวชี้วัด แล้วกด **บันทึกผลการดำเนินงาน**
4. หน้ารายงานจะแสดงข้อมูลใน **ตารางผลการดำเนินงานรายปี** พร้อมค่าเฉลี่ยรายปีและคะแนนถ่วงน้ำหนักของแต่ละเดือนโดยอัตโนมัติ

ข้อมูลรายเดือนถูกเก็บแยกจากผลรวมรายปี การแก้ไขผลรวมในตารางด้านบนจึงไม่เปลี่ยนค่าที่บันทึกไว้รายเดือน

## การวิเคราะห์ผลการดำเนินงาน

หน้ารายงานจะวิเคราะห์ **ภาพรวมผลการดำเนินงาน** และ **ข้อสังเกตเพื่อการพัฒนา** จากเดือนที่มีการบันทึกผลจริง (ค่ามากกว่า 0) โดย

- ค่าเฉลี่ยที่ใช้วิเคราะห์ = ค่าเฉลี่ยของ **เดือนที่รายงาน** ไม่หารด้วย 12 เดือน เพื่อไม่ให้เดือนที่ยังไม่มีข้อมูลทำให้ผลดูต่ำ
- คะแนนเดือนล่าสุดและเดือนที่ดีที่สุดอ้างอิงจากเดือนที่รายงานล่าสุด
- เปรียบเทียบแนวโน้มระหว่างเดือนแรกกับเดือนล่าสุดที่รายงาน
- ข้อสังเกตเลือกจากตัวชี้วัดที่ยังไม่ถึงเป้า 2 อันดับแรก ตัวที่พัฒนามากที่สุด และความครบถ้วนของข้อมูล (สูงสุด 4 ข้อ)
- ตารางผลรายปียังคงใช้ค่าเฉลี่ย 12 เดือนตามโครงสร้างรายงาน และระบุหมายเหตุไว้ใต้ตาราง
- หากยังไม่มีผลรายเดือน ระบบจะแสดงข้อความแนะนำให้เริ่มบันทึกผลแทนการสรุปผลเป็น 0%

## เปลี่ยนหรือเพิ่มภาพอัลบั้ม
1. ภาพกิจกรรมปัจจุบันอยู่ใน `assets/images/` ชื่อ `album-01.jpg` ถึง `album-20.jpg`
2. แทนที่ไฟล์เดิมโดยคงชื่อไฟล์เดิมไว้ ระบบจะแสดงภาพใหม่ทันที
3. หากใช้ชื่อไฟล์ใหม่ ให้แก้รายการ `ALBUM` ใน `assets/js/performance.js`
4. แนะนำภาพแนวตั้งสัดส่วน 3:4 หรือ 9:16 และบีบอัดก่อนอัปโหลด (การ์ดแสดงผลแบบ 3:4)

```js
{ file: "photo-01.jpg", title: "ชื่อภาพ (ใช้เป็น alt text)", category: "ภาพกิจกรรม" }
```

อัลบั้มแสดงเฉพาะภาพโดยไม่แสดงคำอธิบายใต้ภาพ `title` ใช้สำหรับ alt text และ aria-label เพื่อการเข้าถึง ส่วน `category` ใช้สำหรับตัวกรอง

หากเพิ่มจำนวนภาพ ต้องแก้เลข 20 ในลูปสร้าง `ALBUM` และข้อความจำนวนภาพใน `performance.html` ให้ตรงกัน

## การนำขึ้น GitHub Pages

### วิธีที่ 1 — GitHub Actions (แนะนำ)

1. สร้าง repository ใหม่บน GitHub
2. ผูก remote และ push

   ```bash
   git remote add origin https://github.com/<username>/<repo>.git
   git push -u origin main
   ```

3. ไปที่ **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions**
4. ทุกครั้งที่ push ไปที่ branch `main` workflow `.github/workflows/deploy.yml` จะ deploy อัตโนมัติ
5. เว็บไซต์จะอยู่ที่ `https://<username>.github.io/<repo>/`

### วิธีที่ 2 — Deploy จาก branch

ไปที่ **Settings → Pages** เลือก **Deploy from a branch** แล้วเลือก branch `main` โฟลเดอร์ `/ (root)`

> โปรเจกต์นี้ใช้พาธแบบ relative ทั้งหมด จึงทำงานได้ทั้งบนโดเมนหลักและ project page (`/<repo>/`)
